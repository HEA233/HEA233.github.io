Retriever 与 Reranker 的职责

Retriever 的目标是“快且别漏”。它要从几十万甚至上百万文档里迅速找出候选，所以通常接受比较粗糙的相关性判断。

Reranker 的目标是“候选已经不多了，现在仔细判断谁更相关”。它通常可以花更多计算去分析 query 和 document 之间更细的交互。

Retrieval：high recall + cheap
    ↓
Reranking：better precision/ranking + expensive

Reranker 只能重排第一阶段给出的候选。如果正确文档没有进入候选集，它没有机会对文档打分，也无法找回它。这里的关键概念是 candidate recall。如果正确文档已经在候选集内，即使原本位于第 80 名，Reranker 仍有机会把它排进最终 Top 10。

直接让昂贵的 Reranker 给数据库中的所有文档逐篇打分，理论上可以，计算成本通常不合理。

Bi-encoder 与 Cross-encoder

Bi-encoder 分别编码 query 和 document。Document vector 可以提前计算并存储；查询到来时，只需要计算 query vector，再做向量相似度搜索，因此适合第一阶段 retrieval。它的效率来源是 document embedding 可以预先计算并复用，不是“不需要训练”；Bi-encoder 本身也可以训练。

Cross-encoder / joint scoring model 把 query 和 document 一起送进模型，让两边的 token 直接交互，通常能判断更细的相关性。但每个 query-document pair 都要重新计算，成本更高，因此更适合 reranking。

Bi-encoder sacrifices some interaction quality for retrieval efficiency; a joint reranker spends more computation on each candidate to model finer query-document interactions.

MRR：第一个相关结果

MRR（Mean Reciprocal Rank） 只关心“第一个相关结果排在哪里”。如果三个 query 的第一个相关结果分别在第 1、2、5 名：

MRR=1+1/2+1/53≈0.567\mathrm{MRR}=\frac{1+1/2+1/5}{3}\approx0.567MRR=31+1/2+1/5​≈0.567

第一个相关结果越靠前，MRR 越高。它不关心后面还有多少相关结果，适合用户只需要尽快看到第一个正确答案的场景；它不适合衡量 Top-k 中整体有多少好结果。

nDCG：排名、收益与理想排序

nDCG（Normalized Discounted Cumulative Gain） 适合前几名有多个相关结果、且相关程度不同的场景。相关性越高，贡献越大；同样相关的文档，排得越靠前，贡献越大；最后除以理想排序的 DCG。

先使用线性 gain：

DCG@k=∑i=1krelilog⁡2(i+1),nDCG@k=DCG@kIDCG@k.\mathrm{DCG}@k=\sum_{i=1}^{k}\frac{\mathrm{rel}_i}{\log_2(i+1)}, \qquad \mathrm{nDCG}@k=\frac{\mathrm{DCG}@k}{\mathrm{IDCG}@k}.DCG@k=i=1∑k​log2​(i+1)reli​​,nDCG@k=IDCG@kDCG@k​.

IDCG 是把同一组文档按相关性从高到低排列后得到的最大 DCG。相关性等级为 [0, 2] 时，实际 DCG@2 约为 1.26；理想排列 [2, 0] 的 IDCG@2 为 2，因此 nDCG@2 约为 0.63。

DCG 取决于各排名位置上的相关性等级，而非文档身份。两篇同等级文档交换位置，DCG 与 nDCG 不变。改变截止位置 kkk 时，DCG 与 IDCG 都需要重新计算，nDCG 这个比值可能上升，也可能下降。

计算 nDCG@2 时，实际排在第三名的文档不直接贡献 DCG@2，但其相关性仍可能影响 IDCG@2。比如实际排序 [2, 0, 1]：DCG@2 为 2；理想前两名 [2, 1] 的 IDCG@2 约为 2.63，因此 nDCG@2 约为 0.76。

当所有已知相关性等级均为 0 时，DCG 与 IDCG 都为 0，原始 nDCG 公式出现 0/00/00/0；评估实现需要明确并一致地约定处理方式。在非负 gain 下，增加 kkk 不会让 IDCG 下降；如果线性 gain 允许负相关性等级，这个单调性不再保证。

Linear Gain 与 Exponential Gain

常见的两种收益函数是：

gainlinear(rel)=rel,gainexponential(rel)=2rel−1.\mathrm{gain}_{\mathrm{linear}}(\mathrm{rel})=\mathrm{rel}, \qquad \mathrm{gain}_{\mathrm{exponential}}(\mathrm{rel})=2^{\mathrm{rel}}-1.gainlinear​(rel)=rel,gainexponential​(rel)=2rel−1.
相关性等级 0 1 2 3
Linear gain 0 1 2 3
Exponential gain 0 1 3 7

Exponential gain 赋予高度相关文档更大的权重。改变 gain function 可能改变 IDCG 数值，甚至改变两个排序的评价结果。因此，比较模型时需要固定查询、标签、kkk、gain、折扣和 IDCG 为零时的处理约定。

Precision@k 与 Recall@k

两者的区别在分母：

Precision@k=Top-k 中相关文档数k,Recall@k=Top-k 中相关文档数全部相关文档数.\mathrm{Precision}@k=\frac{\text{Top-}k\text{ 中相关文档数}}{k}, \qquad \mathrm{Recall}@k=\frac{\text{Top-}k\text{ 中相关文档数}}{\text{全部相关文档数}}.Precision@k=kTop-k 中相关文档数​,Recall@k=全部相关文档数Top-k 中相关文档数​.

如果整个语料库共有 20 篇相关文档，Top-5 中有 3 篇相关，那么 Precision@5 为 60%，Recall@5 为 15%。前者回答“找出来的有多少是对的”，后者回答“应该找出来的有多少被找到了”。

同一个查询、相同 kkk、完整标签下，两个指标的分母各自固定，相关命中数增加时两者都会增加。kkk 不同则不能仅凭 Precision 的大小推断 Recall 的大小。对固定排序，扩大 kkk 后 Recall 不会下降，Precision 可能上升也可能下降。

只标注 Top-k 时，可以计算这些结果的 Precision@k；如果不知道整个语料库的相关文档总数，通常无法计算真实的全库 Recall@k。

Candidate Budget：候选预算

在两阶段检索系统中，NNN 是 Retriever 交给 Reranker 的候选数量，kkk 是最终返回数量。例如 N=100,k=5N=100, k=5N=100,k=5 表示先召回 100 篇，再重排并返回前 5 篇。

增加 NNN 通常能提高找到相关文档的机会，也会增加计算成本，但不保证最终 Top-5 的质量提高。新候选可能是相关文档，也可能是让 Reranker 排序出错的干扰项。即使候选 Recall 增加，最终 Recall@k 仍可能下降。

如果全库有 20 篇相关文档、候选中有 8 篇相关，而最终只返回 Top-5，即使重排完美，最终 Recall@5 的上限也只是 5/20=25%5/20=25\%5/20=25%；候选 Recall 则是 8/20=40%8/20=40\%8/20=40%。这是质量与延迟的权衡。

Hard Negatives 与 False Negatives

Hard Negative（困难负样本） 是看起来与 query 很相关、但实际上不满足相关性要求的文档。它容易得到较高分数，甚至挤掉真正相关的文档。

False Negative（假负例） 则是实际上相关、却被错误标记为不相关的文档。训练时如果把它当作负样本，模型可能被训练成降低真正相关文档的分数。

从模型高分结果中挖出的样本，只能先称为 candidate hard negative；必须核查真实相关性，才能把它当作可靠负例。高训练损失值得调查，但不能单凭它断定标签错误：可能是模型尚未学会区分，也可能是标注有误。复查标注人员意见不一致、异常高损失、与查询高度相似的样本，有助于检查标签质量。

Pointwise、Pairwise 与 Listwise

  • Pointwise：单独判断一篇文档的相关性。
  • Pairwise：比较两篇文档，学习谁应排在前面。
  • Listwise：把同一 query 的多篇候选作为一组，优化整组排序。

Pairwise Ranking Loss

一种常见做法是同时给模型一篇相关文档（Positive）和一篇不相关文档（Negative），目标是 spositive>snegatives_{\mathrm{positive}}>s_{\mathrm{negative}}spositive​>snegative​。对应的 Pairwise Logistic Loss 可以写成：

L=log⁡(1+esnegative−spositive).L=\log\left(1+e^{s_{\mathrm{negative}}-s_{\mathrm{positive}}}\right).L=log(1+esnegative​−spositive​).

正例分数高于负例且差距越大，损失越小。正例得 8 分、负例得 7 分，与正例得 3 分、负例得 2 分，在这个损失函数下效果一样，因为分数差都是 1；两者同分时，损失为 ln⁡2≈0.693\ln 2\approx0.693ln2≈0.693。

Listwise Ranking Loss

一种 Listwise 方法用 Softmax 把同一 query 的候选分数转换成概率分布，再与相关性标签构成的目标分布比较。Pairwise 关注文档对的相对顺序，Listwise 可以考虑整个候选列表的竞争关系。Listwise 不保证一定更好，采用 Listwise 训练也不意味着推理时必须联合输入整张列表。

Training Loss 与 Evaluation Metric

Training Loss 告诉我们模型是否在优化训练目标，例如 Listwise Cross-Entropy。Evaluation Metric 告诉我们最终排序在任务上表现如何，例如 nDCG@10、MRR。

Cross-Entropy 衡量概率分布，nDCG 使用真实相关性等级和最终排序计算质量。两者不一定同步改善：Loss 下降不意味着 nDCG 必定提高。即使模型分数改变，只要排序、标签和评价规则都不变，nDCG 也不变。计算 nDCG 不需要 Softmax 概率。

比较两个 Reranker 时，应在相同查询、标签、kkk、gain、折扣和边界处理规则下检查排序指标，并查看逐查询变化；不能只看训练损失。
